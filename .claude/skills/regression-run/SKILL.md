# Регрессионный прогон по изменениям

## Что делает

Процедура из шести шагов, каждый оставляет след:

1. **База сравнения.** Тег `last-run`, если он есть. Если тега нет — последний коммит
   на `main`. Если нет и её — `origin/main`, затем `HEAD` (сравнивать не с чем — так
   и написано в отчёте).
2. **Изменения.** `git diff --name-only <база> HEAD` плюс незакоммиченное из
   `git status --porcelain`. Рабочее дерево учитывается намеренно: прогон, который
   молча игнорирует несохранённые правки, отчитывается не о том коде, что лежит на диске.
3. **Сопоставление с областями `docs/spec.md`** по таблице ниже.
4. **Прогон** затронутого **плюс smoke**. Выбор тестов — по заголовкам: каждый тест
   в проекте назван своим `REQ-NN` / `INV-NN`.
5. **Отчёт** `reports/run-<дата>.md`: что изменилось, какие области затронуты,
   что прогонялось, passed / failed / skipped / flaky и **общее число тестов**, вердикт.
6. **Метка.** `git tag -f last-run HEAD` — только если прогон зелёный.

## Таблица соответствия

| Изменённый путь | Область проверок |
|---|---|
| `src/core/round.ts` | REQ-01…REQ-04, REQ-36, все инварианты `INV-*` **+ кросс-проверка** |
| `src/core/validate.ts` | REQ-06…REQ-10 **+ кросс-проверка** |
| `src/core/schedule.ts` | REQ-11…REQ-27, REQ-37, все инварианты `INV-*` **+ кросс-проверка** |
| `src/core/index.ts`, `src/core/types.ts` | полный прогон (публичный контракт) **+ кросс-проверка** |
| `src/ui/**` | REQ-28…REQ-33, проект `e2e` |
| `oracle/**` | кросс-проверка TS ↔ Python |
| `tests/**` | полный прогон |
| `playwright.config.ts`, `tsconfig*.json`, `package*.json`, `eslint.config.mjs`, `scripts/**`, `.github/**`, `.githooks/**` | полный прогон (инфраструктура) **+ кросс-проверка**: здесь же лежат скрипты самой сверки |
| `docs/**`, `sessions/**`, `reports/**`, `.claude/**`, `README.md`, `REPORT.md`, `CLAUDE.md`, `.gitignore` | проверок не требует |
| **всё остальное** | полный прогон, консервативно; файл назван в отчёте отдельной строкой |

Несколько областей объединяются. Smoke — `REQ-05`, `REQ-12`, `REQ-16`, `REQ-26` —
прогоняется **всегда**, в том числе когда менялись одни документы: иначе «прогон»
превращается в слово без прогона.

**Кросс-проверка складывается с тестами, а не заменяет их** (`D-40`). Любая правка
в `src/core/**` поднимает и свои REQ-тесты, и сравнение TS ↔ Python. До внешнего
аудита сверка запускалась только при правке `oracle/**`, и правка ядра проверялась
одним контуром из двух — тем самым, который в `validate.ts` слеп: пять поломок из
тридцати пяти, внесённых аудитором, ловились **только** сверкой.

## Как вызывать

```
cd <корень репозитория>
npm run regression-run
```

или напрямую:

```
node scripts/regression-run.mjs
```

Флаги:

| Флаг | Смысл |
|---|---|
| `--base=<ref>` | взять другую базу сравнения вместо тега / `main` |
| `--no-tag` | не переставлять тег (пробный прогон) |
| `--tag=<имя>` | другое имя метки вместо `last-run` |

## Что остаётся на выходе

- `reports/run-<дата>.md` — отчёт прогона. Второй прогон в тот же день пишет
  `run-<дата>-2.md`, третий — `-3`: файл прошлого прогона не затирается никогда.
- Тег `last-run` на HEAD — база для следующего вызова.
- Артефакты Playwright: `test-results/results.json` (числа берутся оттуда),
  `playwright-report/`, трейсы и скриншоты на падениях (REQ-35).

## Границы и решения

- **Ноль тестов — это провал.** Скрипт считает исходы из `test-results/results.json`
  и завершается кодом 1, если прогон выполнил ноль тестов, если не прошёл ни один,
  если что-то упало, если что-то пропущено или если отчёт нечитаем. «Всё зелёное»
  при нуле выполненных тестов не может пройти как успех (CLAUDE.md 4.4).
- **Тег отмечает проверенную точку, а не последнюю попытку.** На красном прогоне
  `last-run` остаётся на месте — следующий вызов снова возьмёт весь диапазон.
- **Playwright запускается через `node_modules/@playwright/test/cli.js`**, а не через
  `node_modules/.bin/playwright`: на Windows шим — это `.cmd`, и без shell его не
  запустить. Всё остальное — тоже голый `node`, `path.join` и `spawnSync` без
  `shell: true` (CLAUDE.md 3).
- **Проект `e2e`.** Если изменился `src/ui/**`, а проекта `e2e` в
  `playwright.config.ts` нет, скрипт пишет об этом в отчёт как о дыре, а не молчит.
- **Отчёт по исходам, а не по статусам.** JSON-репортер Playwright пишет
  `expected` / `unexpected` / `skipped` / `flaky`. Сопоставление по словам
  `passed`/`failed` дало бы нули — ровно ту ложную зелень, ради которой всё это.
