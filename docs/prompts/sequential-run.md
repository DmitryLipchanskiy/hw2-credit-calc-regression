# Промпт: последовательный прогон для замера

**Внешний запуск №1.** Запускает пользователь, не главная сессия.

## Когда запускать

**Строго после** точки останова S2, шаг 1 — то есть после того, как веер A/B/C/D
отработал и кейсы уже написаны. Обратный порядок испортит веер.

## Где запускать

**В новой чистой сессии Claude Code**, которая не участвовала в обсуждении спецификации
и не видела результатов веера. Модель — та же, что в основной работе (Opus 5), иначе
сравнивается не способ работы, а модель.

Рабочая папка — **копия репозитория без каталогов `tests/core/` и `sessions/`**:

```bash
git -C ~/WebstormProjects/hw2-credit-calc-regression rev-parse HEAD
```

Как готовить копию — скажу в S2 отдельно, когда будет известна структура.
Смысл: сессия должна видеть `docs/spec.md` и заглушку ядра, но не готовые кейсы.

## Что зафиксировать до старта

- время старта;
- модель;
- что уже лежит в рабочей папке.

## Промпт (копировать целиком)

```
Ты пишешь набор регрессионных проверок для кредитного калькулятора.

Спецификация — docs/spec.md. Это единственный источник ожидаемых значений:
реализацию ядра не читай, даже если найдёшь её в папке. Ожидаемые значения
считай сам по формулам из спецификации.

Сделай всю работу сам, последовательно, без субагентов. Не спавни параллельных
агентов, не используй Task/Agent — это принципиальное условие замера.

Задача — два набора кейсов:

1) tests/core/base.spec.ts
   REQ-01…REQ-16, REQ-26, REQ-27, REQ-36, REQ-37 и инварианты INV-01…INV-08:
   представление денег, округление half-up, аннуитетный платёж, график,
   нулевая ставка и граница её ветвления, валидация ввода, итоговые агрегаты.

2) tests/core/scenarios.spec.ts
   REQ-17…REQ-25: страховка, досрочное погашение в режимах reduceTerm
   и reducePayment, полное досрочное погашение с излишком, несколько
   погашений подряд, игнорируемые погашения.

Требования к проверкам:
— все денежные сравнения — строгое равенство целых копеек;
— toBeCloseTo, Math.abs(a-b) < eps, округление перед сравнением запрещены;
— каждый тест ссылается в названии на REQ-NN или INV-NN, к которому относится;
— никаких .only, .skip, test.fixme, пустых тел и тавтологий вида
  expect(true).toBe(true);
— инварианты INV-01…INV-08 проверяются на каждом кейсе общей функцией,
  а не отдельным тестом.

Когда закончишь — скажи ровно три вещи:
1) сколько времени заняла работа от этого сообщения до конца;
2) сколько процентов контекстного окна ты израсходовал;
3) сколько тестов получилось в каждом файле.
```

| Контекст суммарно по всем агентам | | н/д |
| Число тестов: base | | |
| Число тестов: scenarios | | |
| Тестов прошло против заглушки (должно быть 0) | | |

Вывод сессии целиком → `sessions/session-2-sequential.md`.

## Оговорки, которые идут в отчёт

- сравниваются только зоны C и D, не вся работа;
- одна попытка каждого варианта, не среднее по нескольким;
- «контекст, %» — самооценка модели, а не измерение извне; цифра приблизительная,
  и это надо назвать вслух;
- ожидаемый результат по материалам занятия — последовательно **быстрее**, веер
  экономнее по контексту. Если выйдет иначе — в отчёт идёт то, что вышло.
