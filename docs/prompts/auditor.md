# Промпт: финальный независимый аудит

**Внешний запуск №4.** Запускает пользователь в **отдельной сессии**, не в той, что делала работу.

Субагент здесь не годится: он живёт внутри сессии, которая уже во всё это верит.

## Почему из свежего клона

Критерий задания звучит буквально: «результат запускается по инструкции, без „допишите
тут своё“». Проверять это в рабочей папке бессмысленно — там `node_modules` на месте,
hooks включены, браузеры скачаны, тег `last-run` стоит, локальный `.private-denylist.txt`
существует. Всё, что «работает» там, может не работать нигде больше.

## Задача 1. Пройти README сверху вниз

Выполняй каждую команду из README дословно, в том порядке, в каком они написаны.

Записывай ВСЁ, что:
- не сработало или упало;
- потребовало догадки, которой в README нет;
- отсутствует, хотя упомянуто;
- сработало не так, как README обещает (числа, поведение, вывод).

Правило простое: всё, что тебе пришлось сделать сверх написанного, — дефект README.
Если пришлось что-то доустановить, угадать порядок, поправить путь — это находка,
даже если в итоге всё заработало.

ОТДЕЛЬНО: в клоне НЕ БУДЕТ файла .private-denylist.txt — он намеренно не коммитится.
Проверка секретов обязана в этом случае деградировать до общих правил и напечатать,
что локальный список не найден. Если она вместо этого упадёт — это дефект, назови его.

## Задача 2. Проверить, что тесты не фиктивные

Зелёный набор ничего не стоит, если он не замечает поломок. Выборочно сломай
реализацию в src/core/ и убедись, что набор это ловит. Минимум четыре разные поломки.

ПОЛОМКИ ПРИДУМЫВАЙ САМ. НЕ открывай docs/mutations.md до того, как закончишь задачу 2
и запишешь свои результаты: там таблица чужого аудита, и она сузит твой поиск
до уже найденного.

Ориентиры, куда смотреть, — но не список для копирования: округление, знаки и порядок
операндов в формулах, границы циклов и число периодов, начисление страховки, порядок
применения досрочного погашения, ветвление на нулевой ставке. Ищи и то, чего в этом
перечне нет.

Для каждой поломки запиши: что сломал, сколько тестов упало, какие именно.

Поломка, которую не заметил НИ ОДИН тест, — самая ценная находка этого аудита.
Верни код в исходное состояние после каждой проверки (git checkout).

### Сверка после задачи 2

Когда закончишь и запишешь свои результаты — открой docs/mutations.md и сравни.
Отдельным пунктом отчёта:

- что нашёл ты, чего в той таблице нет;
- что есть в таблице, а ты пропустил.

Второе не менее важно первого: оно показывает границы твоего аудита. Не подгоняй
свои результаты под таблицу задним числом — расхождение в обе стороны и есть
содержательная часть этой сверки.

## Задача 3. Сверить заявленное с фактическим

README и docs/ содержат конкретные числа и утверждения. Проверь их сам:

- сколько тестов в наборе на самом деле — совпадает ли с числом в README;
- сколько случаев в кросс-проверке TS ↔ Python — совпадает ли с заявленным;
- существует ли workflow-скилл и работает ли он на чистом клоне;
- совпадает ли список требований REQ-NN в docs/spec.md с тем, на что реально
  ссылаются тесты: есть ли требования, которые никто не проверяет;
- заявлено, что ожидаемые значения берутся из docs/oracle.md, а не из реализации.
  Проверь выборочно, так ли это.
