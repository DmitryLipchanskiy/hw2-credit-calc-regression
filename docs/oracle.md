# Внешние контрольные точки

**Единственный внешний якорь проекта.** Реализация на TypeScript и эталон на Python
написаны по одной и той же [спецификации](spec.md) — значит, они могут разделять ошибку
самой спецификации. От этого страхуют только точки из этой таблицы: значения, полученные
из источника, который спецификации не видел.

**Входы проставляет агент, выходы заполняет человек.** Входные параметры — это покрытие
веток, зона ответственности того, кто планирует проверки; самоподтверждением они стать
не могут. Выходные значения агент **не имеет права** дописывать ни из нашей реализации,
ни из эталона — это превратило бы внешний якорь в зеркало.

Статус: **входы проставлены, выходы не заполнены.** Блокер для начала сессии 2.

---

## Два источника

### Источник 1 — функция `PMT`

Google Sheets, Excel, LibreOffice. Другая реализация формулы аннуитета, написанная
не нами и не по нашей спецификации, считается за минуту.

```
=PMT(ставка_годовая/12; срок_месяцев; -сумма_рублей)
```

Пример для O-01: `=PMT(0,12/12; 60; -1000000)` → ежемесячный платёж в рублях.

Переплата: `=PMT(...)*срок + (-сумма)`, то есть платёж × число месяцев минус тело.

**Применима ко всем кейсам без страховки и досрочного погашения** — то есть
к O-01, O-02, O-03, O-07, O-08. Это шире, чем планировалось: якорь получают все пять
базовых точек, а не три.

`PMT` для нулевой ставки работает штатно: `=PMT(0; 12; -120000)` → ровно 10 000.
Это отдельная проверка нашей ветки REQ-13.

> **Формат.** В русской локали Sheets разделитель аргументов — точка с запятой,
> десятичный — запятая. В английской — запятая и точка. Если формула возвращает ошибку,
> дело почти всегда в этом.

### Источник 2 — публичный кредитный калькулятор

Банковский сайт или портал-агрегатор. Нужен для точек со страховкой и досрочкой,
где `PMT` бессильна.

**Заранее принято:** O-04, O-05, O-06 могут остаться незаполненными. Публичные
калькуляторы редко считают страховку от остатка долга и почти никогда не показывают
помесячный график после досрочки в двух режимах раздельно.

Если источник сценарий не считает — так и писать в примечании: **«внешний источник
этот сценарий не считает»**. Отсутствие точки честнее выдуманной точки, и эта строка
идёт в `REPORT.md` как есть.

## Как заполнять

1. Взять входные параметры строки из таблицы ниже (они уже проставлены).
2. Посчитать в `PMT` — для точек, где столбец «PMT применима» отмечен ✓.
3. Открыть публичный калькулятор, ввести те же параметры.
4. Переписать в таблицу: ежемесячный платёж и переплату **в рублях с копейками**.
5. Записать источник со ссылкой и дату проверки — калькуляторы меняются.

Округление до копейки, без округления до рублей. Расхождение в копейку — это ровно то,
что ищет весь проект; округлив, мы его потеряем (REQ-36).

## Расхождения

Заполняется по ходу работы. Если наш расчёт разошёлся с контрольной точкой —
строка сюда, **до** того как что-либо правится.

| # | Точка | Наш результат | Контрольная точка | Разница | Разобрались? |
|---|---|---|---|---|---|
| | | | | | |

Правка ожидания в тесте допускается только со ссылкой на строку этой таблицы
или на `REQ-NN`, и записывается в [decisions.md](decisions.md).

> **Расхождение — не повод править ожидание.** Сначала выясняется, кто прав: мы, `PMT`
> или калькулятор. У публичных калькуляторов свои допущения — округление платежа вверх
> до рубля, другой день начисления процентов, комиссия внутри ставки. Если прав внешний
> источник — правится код. Если правы мы — расхождение объясняется строкой в этой таблице
> и остаётся в ней навсегда.
