# Регресс кредитного калькулятора

Домашнее задание №2 учебного курса по агентам. **Вариант B4** из Приложения А.

Объект тестирования — аннуитетный кредит: сумма, годовая ставка, срок в месяцах,
досрочное погашение в двух режимах (`reduceTerm` и `reducePayment`) и страховка.
Ядро считает помесячный график, итоговые агрегаты и валидирует ввод.

Стек: **TypeScript + Playwright**, пакетный менеджер — **npm**.

Требования, по которым написаны и реализация, и проверки, лежат в
[docs/spec.md](docs/spec.md) — `REQ-01…REQ-38`, `INV-01…INV-08`. Ссылка на `REQ-NN`
есть в имени почти каждого теста.

**Формат — соло, выбран сознательно.** Задание даёт плюс за команду, но проект был
специфицирован и наполовину сделан в одиночку: спецификация, контракт ядра и веер
из четырёх агентов уже существовали к моменту, когда команду можно было бы собрать.
Изображать команду задним числом — хуже, чем честно сдать соло.

## Как устроено

Четыре части, каждую писал отдельный агент, не видя работы остальных:

| Часть | Где | Что это |
|---|---|---|
| Ядро расчёта | `src/core/` | TypeScript. Единственная точка входа — `calculateCredit`. Деньги — целые копейки |
| Эталон | `oracle/` | Независимая реализация тех же формул на Python, по той же спецификации, другим автором |
| Проверки: база | `tests/core/base.spec.ts` | Округление, валидация, инварианты графика |
| Проверки: сценарии | `tests/core/scenarios.spec.ts` | Досрочное погашение, страховка, граничные случаи |
| Страница и браузерные сценарии | `src/ui/`, `tests/e2e/` | Vanilla HTML + CSS без сборщика, 8 сценариев поверх формы |

Плюс к этому два файла с проверками, которых до аудитов не было:
`tests/core/skeptic-findings.spec.ts` — дыры, найденные агентом-скептиком,
и `tests/core/auditor-findings.spec.ts` — дыры, найденные внешним аудитором
(`sessions/session-4-auditor.md`). Оба вынесены отдельно нарочно: должно оставаться
видно, какие проверки существовали до аудита, а какие появились потому, что аудит
нашёл их отсутствие.

### Два независимых контура

1. **Набор проверок над ядром** — 162 теста, запускаются раннером Playwright.
2. **Кросс-проверка** — одни и те же **290 случаев** прогоняются через TypeScript-ядро
   и через Python-эталон, результаты сравниваются построчно (23 794 строки графиков).
   Расхождение в одну копейку роняет сравнение.

### Откуда берутся ожидаемые значения

Не из реализации. Это главное правило проекта ([CLAUDE.md](CLAUDE.md), п. 2 и 4.6):

- автор кода не проверяет свой код;
- ожидаемые значения — из [docs/oracle.md](docs/oracle.md): внешние контрольные точки,
  снятые человеком с функции `PMT` (Google Sheets / Excel), которая нашей спецификации
  не видела;
- поменять ожидание в тесте можно только со ссылкой на конкретный `REQ-NN` или строку
  `oracle.md`, и такая правка записывается в [docs/decisions.md](docs/decisions.md).

**Где независимость условна — сказано прямо.** TypeScript и Python написаны по одному
документу, поэтому кросс-проверка ловит ошибки реализации, но не ошибки самой
спецификации. От них страхуют только внешние точки из `oracle.md`. Подробнее —
в [REPORT.md](REPORT.md).

Денежные величины сравниваются на **строгое равенство** целых копеек. Допуски
(`toBeCloseTo`, `epsilon`, `Math.abs(...) < ...`) запрещены и блокируются pre-commit
хуком: расхождение в копейку — именно тот дефект, ради которого взят этот вариант.

## Как запустить

### Что нужно поставить

| Инструмент | Версия | Зачем |
|---|---|---|
| **Node.js** | 20 или новее (`engines` в `package.json`) | ядро, тесты, все вспомогательные скрипты |
| **Python** | 3.9 или новее | эталонная реализация и сравнение результатов |

Больше ничего. Python-часть использует только стандартную библиотеку — `pip install`
не нужен.

Проверено на Node v24.16.0 и Python 3.9.6 (macOS). CI гоняет Node 22 и Python 3.11.

### Установка

```
npm ci
```

Эта же команда через `prepare`-скрипт включает pre-commit хук
(`git config core.hooksPath .githooks`) — отдельного шага не нужно.

### Браузер

Проверки над ядром (`tests/core`) работают без браузера, но браузерные сценарии
(`tests/e2e`) открывают реальную страницу. На чистой машине один раз, **после**
`npm ci`:

```
npx playwright install chromium
```

Порядок важен и был поправлен по итогам внешнего аудита: до `npm ci` в каталоге нет
`node_modules`, поэтому `npx` скачивает произвольную свежую версию `playwright`
вместо закреплённой в `package-lock.json` и ставит браузеры под неё. Playwright
на это ругается собственным баннером `WARNING: It looks like you are running
'npx playwright install' without first installing your project's dependencies`.

### Основные команды

Всё в таблице реально существует в `package.json` и было выполнено перед публикацией
этого файла.

| Команда | Что делает |
|---|---|
| `npm test` | весь набор проверок: ядро + браузер. **170 passed** |
| `npm run test:core` | только проверки над ядром, без браузера — 162 из 170 |
| `npm run test:e2e` | только браузерные сценарии — 8 из 170 |
| `npm run build:ui` | компиляция страницы калькулятора в `dist/web/` |
| `npm run serve:ui` | локальный сервер со страницей; сам собирает UI при старте |
| `npm run regression-run` | **workflow**: прогон по изменениям с прошлого раза, отчёт в `reports/` |
| `npm run cross-check` | сборка + 290 случаев через Python-эталон + через TypeScript + сравнение |
| `npm run lint` | ESLint по `src`, `tests`, `scripts` |
| `npm run lint:forbidden` | проверка на запрещённые приёмы: `.only`, `.skip`, `as any`, допуски в денежных сравнениях |
| `npm run build` | компиляция ядра в `dist/` (нужна для `oracle:ts`) |
| `npm run ci:evidence` | сводка по артефактам прогона; падает, если где-то ноль выполненной работы. **Запускать сразу после `npm test`** — см. ниже |
| `npm run check:secrets` | проверка репозитория и истории на секреты и упоминания рабочих проектов; вызывается pre-push хуком |
| `npx tsc --noEmit` | проверка типов без сборки |

**У `ci:evidence` есть порядок.** Команда не запускает тесты сама — она читает
`test-results/results.json`, оставленный последним прогоном, и падает с кодом 1,
если в каком-то проекте ноль выполненной работы. Поэтому её место — сразу за полным
`npm test`. После частичного прогона (например, после `npm run regression-run`,
который гоняет только затронутое) она сообщит `project "e2e" passed zero tests`
и вернёт 1 — это правильное поведение на неправильных входных данных, а не поломка.
Зависимость не была названа, и внешний аудитор, шедший по таблице сверху вниз,
получил красный шаг.

`npm run check:secrets` работает и без файла `.private-denylist.txt` — он локальный
и намеренно не коммитится. В его отсутствие проверка деградирует до встроенных правил
и прямо это печатает: `.private-denylist.txt not found — local word list skipped,
built-in rules only`.

Отдельные шаги кросс-проверки, если нужно запустить их по одному:

| Команда | Что делает |
|---|---|
| `npm run oracle:py` | прогоняет 290 случаев через Python-эталон → `oracle/expected.json` |
| `npm run oracle:ts` | прогоняет те же 290 случаев через собранное ядро → `oracle/ts-results.json` |
| `npm run oracle:compare` | сравнивает два файла построчно |

`oracle:ts` требует, чтобы перед ним отработал `npm run build`.

### Минимальный сценарий проверяющего

```
npm ci
npx playwright install chromium
npm test
npm run cross-check
```

Ожидаемый итог: **`170 passed`** у прогона и `расхождений нет` у кросс-проверки.
Числа перемерены после слияния веток, а не поправлены на глаз.

### Посмотреть калькулятор глазами

```
npm run serve:ui
```

Откроется на `http://127.0.0.1:4173`. Отдельно собирать не нужно — сервер компилирует
страницу при старте. Вёрстка адаптивная, тёмная тема подхватывается из системной.

### Workflow: регрессионный прогон по изменениям

```
npm run regression-run
```

Берёт diff с прошлого прогона (тег `last-run`), сопоставляет изменённые файлы
с областями спецификации, прогоняет затронутые проверки плюс smoke, пишет отчёт
в `reports/run-<дата>.md` и переставляет тег. На красном прогоне тег **не**
переставляется: метка отмечает проверенную точку, а не последнюю попытку.

Флаги: `--base=<ref>` — сравнивать с другой точкой, `--no-tag` — не трогать тег.

Процедура описана в [.claude/skills/regression-run/SKILL.md](.claude/skills/regression-run/SKILL.md).

### macOS и Windows

CI гоняет матрицу `macos-latest` + `windows-latest`, обе ветки обязаны быть зелёными.
Кроссплатформенность обеспечена не обещаниями, а устройством скриптов:

- ни один npm-скрипт не вызывает `python3` или `python` по имени —
  `scripts/python.mjs` перебирает `python3`, `python`, `py` и запускает тот,
  что ответил, и принудительно ставит UTF-8 на вывод (Windows иначе падает
  на кириллице в `print`);
- любая многошаговая или файловая операция — это `.mjs`-скрипт, запускаемый через
  `node`, а не строка шелла с `&&`, `rm -rf` или `export`;
- pre-commit хук вызывает `node`, а не `grep`/`sed`.

Правила, из которых это следует, — п. 3 в [CLAUDE.md](CLAUDE.md).

### Проверки перед коммитом

Pre-commit хук лежит в репозитории (`.githooks/pre-commit`), а не в `.git/hooks`,
и блокирует коммит при находке запрещённого приёма: `.only`, `.skip`, `test.fixme`,
пустое тело теста, тавтология вида `expect(true).toBe(true)`, `as any`,
`as unknown as`, `toBeCloseTo`, `epsilon`/`tolerance` в сравнениях. Обход через
`--no-verify` запрещён правилами проекта.

## Что где лежит

| Каталог / файл | Что внутри |
|---|---|
| `src/core/` | ядро расчёта: `index.ts` (вход), `schedule.ts` (график), `round.ts` (округление half-up), `validate.ts` (валидация), `types.ts` (публичный контракт) |
| `tests/core/` | набор проверок: `base.spec.ts`, `scenarios.spec.ts`, `skeptic-findings.spec.ts`, `auditor-findings.spec.ts`, `invariants.ts` + `invariants-selfcheck.spec.ts` |
| `oracle/` | Python-эталон: `calculator.py`, `run_cases.py`, `compare.py`, `cases.json` (290 случаев) |
| `scripts/` | вспомогательные `.mjs`: `python.mjs` (кроссплатформенный запуск Python), `check-forbidden.mjs`, `run-cases-ts.mjs`, `ci-summary.mjs` |
| `src/ui/` | страница калькулятора: `index.html`, `styles.css`, `app.ts`, свой `tsconfig.ui.json` и `serve.mjs` — локальный сервер без зависимостей |
| `tests/e2e/` | браузерные сценарии и Page Object |
| `.claude/skills/` | workflow-скилл `regression-run` |
| `docs/` | спецификация, план, оракул, журнал решений, мутации, промпты агентов |
| `sessions/` | журнал сессий: промпты пользователя дословно, выдержки прогонов |
| `reports/` | отчёты `regression-run`, по файлу на прогон. Рабочие артефакты Playwright (`playwright-report/`, трейсы, скриншоты) в репозиторий не попадают — они в `.gitignore` |
| `.githooks/` | pre-commit хук |
| `.github/workflows/ci.yml` | матрица macOS + Windows |

Генерируемые файлы `oracle/expected.json` и `oracle/ts-results.json` в репозиторий
не попадают (первый — около 5 МБ), они воспроизводятся командами `oracle:py`
и `oracle:ts`.
